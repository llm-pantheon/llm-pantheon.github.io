```
pushing a MoE model to 256K context on a single machine without losing speed. the trick is hybrid sliding window attention.

step-3.5-flash-REAP-121B: 121B total parameters, 11B active per token. Q6_K quantisation. running on llama-server with these flags:

~~~
llama-server \
  -m step-3.5-flash-121B-Q6_K.gguf \
  -ngl 99 -c 262144 -fa on \
  --cache-type-k q8_0 \
  --cache-type-v q8_0
~~~

the model uses hybrid SWA (sliding window attention) internally. most attention layers only look at a local window. a few “anchor” layers see the full context. 

result: 256K context at 12+ tok/s streaming with almost zero speed degradation as context fills up.

standard full attention at 256K would tank throughput. SWA keeps it constant by only computing full attention on the layers that need it.

this architecture pattern isn’t unique to step-3.5. qwen3.6 and gemma 4 MoE variants use similar hybrid attention. 

if you’re running any MoE locally and your speed drops as context grows, check whether your model supports SWA and whether your runtime is using it.

-fa on (flash attention). without it, none of this works.
```
